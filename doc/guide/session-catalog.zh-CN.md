# Code 的统一会话列表

Code 侧栏以最近更新时间列出已知本地工程与 SSH 工程的真实会话，不再按当前执行位置切换成两份列表。顶部主题菜单支持 All sessions、Local、SSH 与已知主机；搜索匹配会话标题、首条消息、工程及位置。普通 Chat 仍保留独立的零工具历史，不与 Code 后端混用。

- 列举只查询已保存的本地工程/临时工作区和已知 SSH 根目录；不扫描整台机器。
- 列表不会连接服务器、索取密码、改变前台位置或创建会话 worker。只查询已有 SSH 连接。本地来源在读取前使只读 preview 列表缓存失效，避免新会话被旧的空列表缓存遮住；仍不绑定/聚焦 native worker。
- 只有可证实为工具/模型发现自动创建、完整且无消息、未命名且未被用户采用的空白 SSH 会话才隐藏；不自动删除。新探测 runtime 不预先创建 JSONL，来源存于私有 `.desktop-purpose` sidecar，并保留探测复用身份。内部 get_messages/get_tree 等只读水合不再误标为用户打开，清空 pending bind 不清掉已选真实会话。无法证明来源的旧空会话、明确打开/创建/重命名的会话、含消息及不完整元数据均保留。
- 每条会话保留服务器指纹、工程和会话身份。点击其他位置的历史才显式切换；断开连接时可在应用内重连，取消握手后保留 SSH 意图与执行锁，必须明确选择 Local 才解锁；旧握手回复不能覆盖较新的前台选择，也不重发 prompt。主机身份或目录规范路径变化会拒绝打开。
- 当前 SSH 会话元数据缓存在内存中：同一次应用运行可显示已断开连接的缓存行；应用重启后需要一次显式连接才能重新获得远端行，不保证离线历史完整性。
- 每次最多返回 500 个匹配项、查询 500 个来源，最多两个来源并发；主机来源轮转取样，避免大量 Local 根占满 SSH 槽位。过滤/搜索先在服务端执行再截断；搜索输入有 250ms 防抖，不会先截掉旧 SSH 会话再过滤。达到上限明确提示缩小范围；不声称枚举无限历史或提供完整分页。保留局部错误和显式 Retry，超大/不完整远端文件不捏造消息数。

## 手动删除

每行的 `⋯` 或右键菜单提供 Delete，必须在应用内明确确认；只有后端成功才移除该行。SSH 删除只作用于已连接且身份匹配的该工程私有历史文件，校验 session ID、所有者、inode、私有权限、单链接及 sidecar，不运行 shell。繁忙、请求尚在途、不能确认退出或文件被替换时拒绝，不自动 abort 活动任务。仅停止被删会话自己的空闲 runtime，不影响其他会话或终端。

删除当前历史后返回同一执行位置/工程的空白视图，不切换到 Local，也不创建新历史文件。已经切换到别处时，晚到的删除结果不清空新视图。断开的主机需要用户显式连接后才能删除；不会为了删除自动连接。旧的不明来源空会话不会批量清除，可逐条确认删除。Node 的校验后 pathname unlink 不是同 UID 对抗沙箱。

`code.sessions.list` 只接收过滤/搜索条件并访问服务器已知位置；`code.sessions.prepareOpen` 对明确点击的既有 SSH 根执行规范路径复验，不在该异步阶段改变前台位置。普通文件、终端、模型和运行请求仍走原有严格身份路由。
